# Smart Medical Note Assistant

A Streamlit application that transforms unstructured practitioner notes into structured **SOAP (Subjective, Objective, Assessment, Plan)** documentation using Google's Gemini API.

The project demonstrates prompt engineering, API integration, input validation, structured model output, Pydantic validation, and retry handling.

## Features

- Converts free-text practitioner notes into a structured SOAP note.
- Supports practitioner-role context in the prompt.
- Requests JSON output from Gemini and validates it with a strict Pydantic schema.
- Rejects empty notes and notes longer than 10,000 characters.
- Retries selected temporary API failures with exponential backoff (up to three attempts).
- Handles authentication, quota, connection, timeout, and API errors.
- Displays the four SOAP sections and allows the result to be downloaded as JSON.
- Loads API credentials from environment variables.

## How It Works

1. Practitioner enters notes in Streamlit.
2. The application trims and validates the input.
3. A prompt asks Gemini to organize source information into SOAP sections without inventing missing details.
4. Gemini returns JSON.
5. Pydantic validates the required fields and rejects unexpected fields.
6. The validated note is displayed and can be downloaded.

## Getting Started

### 1. Clone the repository

```bash
git clone https://github.com/duaajaved321/Smart-Medical-Note-Assistant.git
cd Smart-Medical-Note-Assistant
```

### 2. Create and activate a virtual environment

**Windows PowerShell**

```powershell
python -m venv .venv
.venv\\Scripts\\Activate.ps1
```

**macOS / Linux**

```bash
python -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Configure Gemini

Create a local `.env` file using `.env.example` as a guide:

```env
GEMINI_API_KEY=your_gemini_api_key_here
GEMINI_MODEL=gemini-2.5-flash
```

Get an API key from [Google AI Studio](https://aistudio.google.com/app/apikey). The model can be changed through `GEMINI_MODEL` without editing source code.

**Never commit `.env` or share API keys.** The `.gitignore` excludes local secrets. Use fictional notes while testing.

### 5. Run the application

```bash
streamlit run main.py
```

Open the local URL shown in the terminal, usually `http://localhost:8501`.

## Example

**Practitioner notes**

```text
- Patient reports fever for 2 days
- Headache
- Temperature: 101°F
- No vomiting
- Assessment: Suspected viral illness
- Plan: Rest and fluids
```

**Illustrative SOAP output**

```json
{
  "subjective": "Patient reports fever for 2 days and headache. No vomiting.",
  "objective": "Temperature: 101°F.",
  "assessment": "Suspected viral illness.",
  "plan": "Rest and fluids."
}
```

Actual wording is generated by the configured model and must be reviewed.

## Validation and Error Handling

- Empty input and inputs over 10,000 characters are rejected.
- The model response must be valid JSON.
- All four SOAP fields are required and must be non-empty strings.
- Unexpected JSON fields are rejected.
- Temporary rate-limit, timeout, connection, and server failures are retried up to three attempts.
- Common authentication, invalid-request, quota, and API failures receive user-friendly messages.

## Limitations and Responsible Use

- SOAP is the only supported note format.
- No database storage is implemented.
- This is a learning/demo project, not a certified clinical documentation system or medical device.
- Generated content can omit or misrepresent information. A qualified clinician must verify every section against the source notes.
- Do not use the model as a source of diagnoses or treatment decisions.
- Do not submit identifiable patient data unless authorization, consent, and a compliant environment have been established.
- Notes are sent to Google's Gemini API. Review the provider's applicable privacy and data-handling terms before using sensitive information.
